邁向開放原始碼：雲端運算與人工智慧的演進

這篇文章探討一家科技公司的轉型之路，從依賴專有企業產品，逐步走向開放原始碼的生態系統，特別是在雲端運算和人工智慧領域。

關鍵轉變：

  • 從企業產品到開放原始碼： 公司正積極從依賴專有企業產品轉向採用開放原始碼解決方案，這源於對更強的控制權、靈活性以及成本效益的追求。
  • 回饋開放原始碼社群： 公司積極回饋開放原始碼社群，參與像是 Kubernetes 和 LangChain 等項目，認可合作開發的價值。
  • 混合策略： 公司承認純粹的開放原始碼模式並不總是最佳選擇，並願意在必要時利用雲端平台服務。
  • 挑戰與策略： 轉向開放原始碼面臨的挑戰包括管理複雜性和確保安全性。公司通過對工具、培訓和內部專家進行戰略性投資來應對這些挑戰。
  • Kubernetes 的核心地位： Kubernetes 成為公司雲端基礎架構的核心。他們正在探索像是 Pakito 和 Backstage 等工具，以簡化 Kubernetes 管理。
  • 生成式 AI： 公司正在實驗使用 LangChain 等生成式 AI 工具，以利用大型語言模型的强大功能。

總體而言，演講者強調了公司對開放原始碼原則的承諾，以及其在雲端技術和 AI 領域不斷變化的環境中持續努力。

從 CF Push 到 Kubernetes 的轉型：

這個討論重點關注從使用平台如 CF Push 轉向 Kubernetes 的過程。

關鍵點：

  • Kubernetes 的挑戰： 儘管 Kubernetes 提供許多優勢，但由於其學習曲線，其採用可能會變得複雜。
  • 轉型策略：
    • Pakito： 提供類似 CF Push 的簡化體驗的工具。
    • 現有 ECS 應用程式： 一些應用程式已經建立在 ECS 上，這使得轉向 Kubernetes 更為直接。
    • Backstage： 一個旨在通過 GUI 簡化 Kubernetes 管理的開源平台。
  • 長期目標： 演講者希望最終實現純 Helm 部署狀態。
  • 內部開源模式： 公司採用內部開源模式，使 Helm 圖表和庫可供內部使用。
  • 雲端平台： 公司目前使用 Amazon EKS (Elastic Kubernetes Service) 來部署其 Kubernetes 環境。

這個討論突顯了遷移到 Kubernetes 所涉及的挑戰和策略，強調了簡化此過程的工具和資源的重要性。
